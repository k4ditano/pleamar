# Known limitations

Everything known to be half-done, **with its fix plan**, to be crossed off as it goes. Written down as it comes up, not at the end.

**Severity**: 🔴 blocks what comes next · 🟡 will hurt soon · ⚪ rare case. When something is fixed it moves to the table below with its date; it is not deleted.

## Cross-platform

The rule: **everything system-related lives behind `src/plataforma/`**, and the core only uses crates that exist on Linux, Windows and macOS. The guard is `./portable.sh`, which compiles the core against all three; today it passes.

| Piece | Linux | Windows | macOS | How it gets finished |
| --- | --- | --- | --- | --- |
| Core (model, renderer, layers, gestures, text, images) | ✅ | compiles | compiles | — |
| Windows (`plataforma::atender`, `Ventana`) | ✅ Wayland | ✅ Win32 + DX12/DirectComposition | ⬜ says it does not know how and exits | Windows has transparent panels and normal windows, one copy per selected monitor, dynamic input regions, pointer/keyboard/wheel input, DPI changes, anchors and AppBar reservation. Named popups and monitor hot-plug still need their own lifetime work. **macOS**: borderless `NSPanel`, floating level, non-opaque `CAMetalLayer`; transparent areas already let the click through; `reserva` does not exist and is ignored |
| Icons by name (`plataforma::icono`) | 🟡 naive lookup | ⬜ returns nothing | ⬜ returns nothing | Windows: `IShellItemImageFactory`. macOS: `NSWorkspace.icon(forFile:)`. Both give a bitmap, not a path: `icono` will have to be able to return pixels |
| System fonts | ✅ `fontdb` + fontconfig | ✅ `fontdb` (runtime checked) | untested | `fontdb` reads each system's font folders; macOS still has to be seen running |
| Global pointer | ⬜ Wayland forbids it | easy (`GetCursorPos`) | easy (`NSEvent.mouseLocation`) | On Linux, through the compositor's IPC. It is a fact in the data graph |
| Runtime smoke test | ✅ | ✅ Intel Iris Xe, DX12, two monitors, fractional DPI and premultiplied alpha | ⬜ | CI should still compile all three and start Windows with a software adapter when one is available |

### Services and the bar

| # | Limitation | Severity | How it gets fixed |

| P1 | A `path` holds **a single subpath** (one `move`) and **192 points** once flattened, curves included; and it does not know how much room it takes in a layout, so there it has to be told with `size:`. ### The logic (Luau)

| # | Limitation | Severity | How it gets fixed |
| --- | --- | --- | --- |
| U1 | Approving a plugin is **all or nothing**, and through the command line (`pleamar --aprobar`): there is no window asking when the plugin shows up, and there is no approving `date` and denying `notify-send`. Permissions are still by command name, with no limit on arguments or paths. And a scene that gets opened grants itself its own without anyone asking: opening it is the decision | 🟡 | A pleamar scene that asks (which is exactly what pleamar knows how to do: a surface with two buttons), launched by the program itself when it finds an unapproved plugin; approving piece by piece, storing the approved list and not just the fingerprint; and for commands, an argument pattern (`run: "date +%H:%M"`) |
| U3 | The 2 s cutoff is for a stuck handler, but **not for the plugin**: one that always gets stuck keeps trying and burns a core now and then. `require` loads modules from that logic's folder, and there is no way to share one between two plugins | ⚪ | Counting the cutoffs and, after three in a row, stopping the plugin and saying so; and a read-only folder of shared modules (`require("pleamar/…")`) |
| U5 | `./portable.sh` checks Windows and macOS **without** Luau: there is no C++ cross-compiler here | ⚪ | Installing `mingw-w64-gcc`, or CI on all three systems |
| U6 | The error for a misspelled name does not carry the script line: Luau's traceback stops at "[C]" | ⚪ | Asking for the traceback at the caller's level (`debug.traceback` at level 2) |

### The language

| # | Limitation | Severity | How it gets fixed |
| --- | --- | --- | --- |
| G12 | A model is **expanded in full at load time**, and its cap is 256 records. A list of thousands already fits and can be dragged (the scene declares the window with `content:` and `for … from`, and tells the logic with `on change`), but **those four lines are written by whoever writes the scene**: the layout does not know it is virtualizing. And there is still **no identity**: if the first record is removed, the rest change content instead of moving up into place | 🟡 | `window rows` in a layout with `view:`, so it sets the `content`, the copies' offset and the notification itself. Underneath, the real thing: the renderer instantiating the body of the `for` per record —properties, zones and rules that are born and die—, with `key: r.id` |
| G18 | The compiler checks **enums** (what they are compared against, that they stay out of arithmetic), but not the other types: a yes-or-no and a number mix with no warning, which is convenient (`r.separator * 21`) and sometimes a bug. An enum is not valid as a component parameter type (it is passed as `number`). And a tree is walked with a `for` written per level: there is no component that puts itself inside itself | ⚪ | `enum` as a parameter type, with the list coming from whoever passes it; and recursive components with a cap —`Branch(c)` inside `Branch`— that the expansion cuts at the list's depth |
| G19 | Text with slots knows about live texts, decimal numbers, `upper`, `lower` and optional spans. It knows durations (`{secs, time}` → `1:07`), but **does not know** about times of day or dates (`{now, "HH:mm"}`: the bar's clock is still put there by Luau every second), thousands separators, plurals (`1 aviso` / `3 avisos`), or picking a text according to a condition (`{muted ? "silencio" : "…"}`). And a template is only valid as the content of a `text`: not in `placeholder:` and not as the source of an `image` | 🟡 | A time slot the renderer resolves on its own (and that wakes up once a minute, not once a second); `{n, plural: "aviso", "avisos"}`; and an `if(cond, "a", "b")` between texts, which is the same `if` as in expressions |
| G20 | Data goes **from the logic to the scene**, not the other way round: a rule cannot change a field (`r.checked = not r.checked`), so any change takes the long way round through Luau | ⚪ | Letting an effect write to a numeric field —underneath it is a fact, and that is already possible— and telling the logic with `model:rows` |
| G15 | The layout knows row and column with gap, padding, align and anchor (`anchor: right`). No line wrapping, no "take up whatever is left", no minimums or maximums. A `group` with no `size:` takes up whatever its last child does, by accident more than by design | 🟡 | `grow:` on a child (splitting what is left over from the layout's `size:`), `wrap`, and a group with no size taking up the union of its children |
| G16 | Each child's position is the sum of the previous ones, written out in full: with *n* children the expressions grow as *n²*. Twenty go unnoticed; two hundred do not | ⚪ | Shared subexpressions: `Expr` becoming a graph and each partial sum being evaluated once per frame |
| G17 | A text's measurement arrives one frame late, so a layout with texts settles over one or two frames at load. With a spring it is invisible; without one, a flicker | ⚪ | See T12 |
| G5 | The messages are in English now (see Fixed), but **only in English**: whoever does not read it is left exactly where whoever did not read Spanish was before. And a tokenizer error (an unclosed quote) still stops reading dead | ⚪ | Once there is someone to do it for: a key per message and a table per language, chosen by `LANG`. The work of pulling the 210 literals into one place would already be half done |
| G7 | On reload, changes to `surface` are not applied (S1), and whichever gesture was playing and the pending delays are lost | ⚪ | Reconfiguring the surface; keeping the gesture if it still exists under that name |
| G9 | The language server knows about names and about where they are used (see Fixed), but **renaming does not touch the logic**: if a `.luau` writes `fact.volume`, that stays a manual job (the compiler does warn, at least). It does not complete a record's fields (`r.label` inside a `for`), and there is no tree-sitter highlighting, so Zed and whoever only speaks that language are left without colors | ⚪ | The logic would need understanding Luau, which is another language: at most, searching for `fact.nombre` and `text.nombre` as plain text and offering that separately. A record's fields ask for knowing which model each `for` is, which the compiler already knows. The tree-sitter grammar is for another day |
| G11 | Hot reload checks the file's timestamp four times a second | ⚪ | It works on all three systems, which is why it was done this way. If it becomes a nuisance: the `notify` crate |
| G25 | The reference's **vocabulary** can no longer fall out of date (see Fixed), but **the EBNF can**: the shape of each statement —what follows what— is still hand-written text, and the only thing guarding it is the examples that get compiled. And the coverage test checks that each word *appears* in some test, not that it is used where it belongs | ⚪ | A grammar that both things come out of —the parser and the EBNF— is too much for what is here; cheaper: one minimal example per production, generated from the EBNF, that has to compile |
| G26 | The **language words are not reserved**: a fact can be called `text` or a property `for`, and whatever error comes out afterwards will not say why. And the version number **comes with no migration**: when 0.2 arrives, a 0.1 file will either be read or not, with nobody to rewrite it | ⚪ | Rejecting a declaration whose name is a language word, with the list in plain sight. And `pleamar --migrar fichero.plm` once there is a first breaking change: while the first number is 0, what changed is written down in note 11 |
| G21 | `import` brings **everything, with no surname**: there is no `import "menu.plm" as menu` and no `import { MenuRow } from …`, so two libraries with a component of the same name cannot be used together (it is reported, but there is no fixing it from the scene) | 🟡 | `as nombre` adding a prefix (`menu.Row(r)`) and a list of what is wanted. The per-scope alias mechanism already exists |
| G22 | A plugin **has no surface of its own**: it lives inside the scene that imports it. If something needs its own, it is a scene; and two scenes share no state | ⚪ | Several scenes running in the same process (S2 asks for this too) and talking to each other through events named by scene, the way it is already done from outside with `--decir` |
| G24 | Libraries are looked up **only next to whoever imports them**. There is no system folder and no user folder (`~/.local/share/pleamar/lib`), and no versions | ⚪ | A list of folders to search, behind `plataforma/` (on each system they are somewhere different), and `import "pleamar/menu"` with no extension for the installed ones |

### Text and images

| # | Limitation | Severity | How it gets fixed |
| --- | --- | --- | --- |
| T12 | A text that appears **for the first time** is not visible until the workshop delivers it (one or two frames); one that *changes* shows the previous one meanwhile. And a text's measurement reaches the expressions one frame later | ⚪ | Whatever is already in the scene when it loads is asked for before the window exists. For the rest: composing twice on the frame where a measurement changes |
| T3 | A single 2048² RGBA atlas: 16 MB of VRAM even when it is nearly empty. If it fills up, the new glyphs are not painted (it warns on the console) and nothing is recycled | 🟡 | Starting at 512² and growing; evicting by shelves whatever has gone longest unused; the glyph masks in a single-channel atlas, which takes a quarter of the space |
| T4 | Glyphs are rasterized at the scale of the **sharpest** render surface; the others see them scaled down. With one monitor at 2 and another at 1, on the one at 1 the text comes out a touch soft | ⚪ | One atlas per scale, and each render surface having its own `uv`: that asks for a table of elements per render surface instead of a shared one |
| T5 | Text under a transform that scales is resampled (scaled up, it comes out soft), and rotated it does not land on whole pixels | ⚪ | Rasterizing at the transform's `escala × factor` once it has been still for a few frames |
| T6 | No rich text (bold or a color mid-paragraph), no letter spacing, no underline, no selection and no editing | 🟡 | `cosmic-text` already has spans with attributes: exposing `Contenido::Rico`. Editing is another project (IME included) |
| T7 | When lines are broken, a space is left at the start of the new line | ⚪ | Looking at how `cosmic-text` treats the trailing space with `Wrap::WordOrGlyph`; if there is no setting for it, trimming it when placing the glyphs |
| T8 | A template is assembled **on every frame** that gets painted, even when nothing has changed: a new string per text with slots. Not noticeable with dozens; with hundreds, yes | ⚪ | Keeping the assembled string next to what its parts were worth, and redoing it only if one of them changed |
| T9 | Images have a maximum size declared by the scene. No URL, no GIF, no nine-patch. When the scale changes they are all re-rasterized | 🟡 | A disk cache of the already-rasterized SVGs; size taken from the destination instead of declared |
| T10 | Icon lookup does not read the `index.theme` files and does not know which theme is in use: it tries the usual ones and takes the first one | 🟡 | The real freedesktop lookup (current theme, inheritance, sizes). It lives in `plataforma/` |
| T11 | Linear gradient only; no radial, no blur, no masks | 🟡 | The radial is ten lines of shader. Blur asks for another pass per layer: the opacity-layer infrastructure already works for it |
| T13 | **Images requested by the data are never evicted from the atlas.** Every distinct icon holds its slot until the scene or the scale changes; with a full atlas, the new ones do not show up. A launcher is a few hundred 24 px icons and fits easily; a cover-art viewer does not | 🟡 | Tracking each slot's last use and recycling the oldest by shelves; or a second atlas page (`texture_2d_array`, which the shader already uses for the layers) |
| T14 | A live image that is not found paints nothing: there is no fallback image. (And many are not found because of T10: here, Avahi's two) | ⚪ | `fallback: icon "application-x-executable"` on the `image`; and fixing T10 |

### Painting

| # | Limitation | Severity | How it gets fixed |
| --- | --- | --- | --- |
| P4 | A group with opacity inside another one gets no layer of its own: it multiplies. With more than four blending at once, the extra ones do too | ⚪ | A stack of layers instead of four fixed ones, and painting the inner ones before the outer ones |
| P5 | With a different scale on each axis, the edge antialiasing is approximate | ⚪ | Measuring the distance gradient in the shader (`fwidth`) instead of a fixed factor |
| P6 | The gradient and the light live in the group's space: if the shape rotates *by itself* (`.girada`) they do not rotate with it | ⚪ | Evaluating the paint in the space of the body's first shape |
| P7 | **Every glyph is an element**: a paragraph is hundreds. There is no cap any more (the stores grow), but it is extra work for the graphics card | ⚪ | One element per *line* of text, walking its glyphs in the shader. And the nested clips that clip by their shape are still four: the outermost ones clip by their box (it warns once) |
| P11 | **Presenting a frame costs ~0.5 ms of CPU no matter what**, whatever it draws: 0.10 ms to record the commands, 0.20 to close the encoder and 0.20 to submit it and present. That is wgpu's floor on top of Vulkan, and it is what makes animating at 60 Hz cost ~4.3% of a core even when all that moves is a circle (measured with `PLEAMAR_CRONO=1`, which prints the breakdown). The vsync wait is 16 ms of sleep, not of CPU | 🟡 | A single `submit` for all the frame's render surfaces instead of one per render surface; reusing the `CommandEncoder` when wgpu allows it; and looking at whether a precooked `RenderBundle` saves the `finish`. For reference: Quickshell doing the same spends 11.9% |
| P8 | The draw list is rebuilt in full on the CPU every frame, changed or not | ⚪ | Rebuilding only the ranges whose properties changed; 2000 shapes cost 0.7 ms today |
| P9 | The first frames after waking do not wait for the screen: the animation clock runs on CPU time, not on presentation time | 🟡 | `wp_presentation` on Wayland (and its equivalents) to know when each frame was shown, and advancing the springs with that time |
| P10 | One frame in ~400 drops to 33 ms. Not investigated | 🟡 | Measuring with GPU timestamps to find out whether it is pleamar's or the compositor's |

### Surfaces and input

| # | Limitation | Severity | How it gets fixed |
| --- | --- | --- | --- |
| E1 | **Wheel, buttons, drag, hold, keys and cursor are tested with the fake script**, which comes in through the renderer. The Wayland side —that the notches arrive with their sign, that the cursor changes, that the keyboard arrives with `on_demand`— nobody has seen with a real mouse | 🟡 | Abel trying it on the bar: the wheel over the volume, dragging the little bar, the speaker, and the pointing hand over the workspaces |
| E4 | The wheel adds the vertical and the horizontal together, and a touchpad is turned into notches by eye (15 px per notch). Dragging a list works now, but **with no inertia**: on release it stops dead, it does not keep gliding | ⚪ | `wheel.x` and `wheel.y` separately, and continuous scrolling in pixels. | E5 | The right button closes the program where the click lands on no zone | ⚪ | It is the prototype's emergency exit. | E6 | A zone being dragged inside an anchored layout moves under the mouse if the layout changes size. Today it is avoided by hand, giving a fixed width to whatever changes | ⚪ | `min_width:` on the children, or freezing the layout while a drag lasts |
| E7 | **No IME**: Japanese cannot be typed in the input field and there is no composing with an input method. Dead keys (´ + a) do work, since xkb resolves them | 🟡 | `zwp_text_input_v3` on Wayland, TSF on Windows, `NSTextInputClient` on macOS, all three behind one `plataforma::Ime` that hands the renderer "text being composed" and "committed text" |
| E8 | **The input field, the focus and the drop are tested with the fake script**, which comes in through the renderer. Nobody has seen them with a real keyboard: `keyboard: exclusive while open` (left untested so as not to take Abel's keyboard away mid-task), `on blur` arriving on a click outside with `on_demand`, or a real drag from Dolphin | 🟡 | Abel trying it with the launcher: opening it with the bind, typing, Escape; and dropping a file onto a test scene. **Careful: with `exclusive` the compositor does not release the focus on a click outside**, so `on blur` does not close there — it would need `hyprland-focus-grab` or a full-screen zone |
| E9 | The input field is **single-line**, with no undo (Ctrl+Z), no double click to pick a word, and no password field | ⚪ | `lines:` on `input` with the same `Maqueta.cursores` (it already gives each letter's line); a stack of states in `Edicion`; `mask: "•"` |
| E10 | A drag can be **received**, but not started towards another application. And only `text/uri-list` and `text/plain` are accepted | ⚪ | `wl_data_source` when dragging a zone with `drag: texto`; on Windows and macOS, their `IDropSource` and `NSDraggingSource` behind `plataforma/` |
| E11 | **The global shortcut depends on the compositor**: it is a bind of its own that launches `pleamar --decir`. And the commands from outside are a Unix socket: on Windows `--decir` does not exist yet | 🟡 | A named pipe on Windows (`\\.\pipe\pleamar-ESCENA`) behind the same function. For the shortcuts: `RegisterHotKey` on Windows, `CGEventTap` on macOS, the `GlobalShortcuts` portal on Linux; with a `shortcut: Super+space` in the scene that for now only warns that the bind is needed |
| P13 | Frames are paced by the renderer's own clock at the monitor's period, not locked to its vblank (see P12 in Fixed): over a long animation the two can drift by a frame, which would show as one repeated frame now and then. Not seen so far | ⚪ | Pacing on the compositor's frame callbacks or `wp_presentation` instead of a timer: it means reaching under `wgpu` for the Wayland surface, behind `plataforma/` |
| B15 | The **network** service is read-only —it says which one and how well it comes in, but cannot connect, disconnect or turn the radio off— and there is **no bluetooth service at all**. A control centre's Wi-Fi and Bluetooth switches can be drawn and cannot be worked | 🟡 | NetworkManager over D-Bus for the first, BlueZ for the second, both in `plataforma/sistema.rs`; and with them, `network.*` and `bluetooth.*` commands |
| S1 | A surface's size is declared by the scene and is fixed: **it does not grow with what it holds**. A card with `shadow: 0, 18, 44` needs 62 px of room below it, and without them the shadow stops dead against the edge. This much is not pleamar's alone —a layer-shell surface asks for its size on both sides, and Marea raised its own ceiling by hand three times, 520 → 640 → 880, with a note in `core/Theme.qml` saying the symptom pointed nowhere near here— but that does not make it right. What **was** pleamar's own fault is that nothing said anything, in a runtime whose whole promise is that mistakes are caught: since 2026-09-20 the renderer says it (see Fixed). Saying it is not growing it. And on hot reload the surface is not reconfigured (it has to be relaunched) | 🟡 | The scene being able to change its `Superficie` and the platform reconfiguring it. Growing on its own is a separate question and probably a bad idea while something is animating: a surface that resizes every frame is a surface that flickers. The likely shape is `size: fit` for what does not move. It is dodged by declaring it large: the input region lets the click through |
| S2 | One surface per monitor already has its own state (see Fixed), but **the cap is fixed** (`each max 4`): four copies are expanded even when there is one monitor, with their properties and their zones.
